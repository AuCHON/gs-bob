## 〇、增量基准(降级自审产出)

1. **问题**:"先得 X 分或计时分高者胜"为单句压缩语,两个获胜条件需读者自行拆解,不满足"一眼就知道"。
2. **方案**:拆为两条图标条件行(项目无 emoji 方针 → 沿用内联 SVG):
   - 奖杯图标 +「先得 **N** 分即胜」(N 金色加粗,动态)
   - 时钟图标 +「时间到 · 分高者胜」
3. **范围**:侧栏比分面板规则区(容器 .win-rule)与开始菜单(副标题改短句+规则组)两处同步改造;README 为主动阅读文档,措辞不变。
4. **不变**:获胜逻辑/设定机制/时长口径文案(durationLine)不动。
5. **验收**(第 1 轮回写):每条条件短语 ≤8 字符(不计空格/分隔符);数字仍随设定联动;菜单与侧栏两行文案逐字一致;副标题与侧栏 goal 措辞同构(均可读出"撞下平台即可得分")。
6. **测试**(第 1 轮回写):mock 无法感知 HTML 静态层——文案断言以 fs 读 index.html 正则实现(HTML 静态层契约);JS 侧数字联动断言(ruleScoreNum/subScoreNum)。
