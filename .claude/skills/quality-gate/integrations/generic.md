# 任意工具 / 纯对话接入（通用手册）

没有子代理机制的工具（或直接用网页版 LLM）也能完整执行本流程——核心是
**用"新会话"获得独立上下文**，代替子代理。

## 角色卡

- `prompts/requirement-adversary.md` = 需求对抗角色卡
- `prompts/implementation-adversary.md` = 实现对抗角色卡
- `SKILL.md` = 主会话（你/主模型）的操作手册

## 手动流程

先做预筛选（SKILL.md 第 0 步）：非开发回合（纯问答、排查诊断、用完即弃的验证代码）
到此为止，无需任何阶段。只想审查、不开发（点名/评估式问法）：也跳过阶段 A/B——
新开会话贴实现对抗（对象为代码）或需求对抗（对象为需求/设计文档）角色卡 + 片段/
范围，发现表直接回复用户（要修、或用户要求归档才落盘，终态"已审计"），不擅自修复；要修再回完整流程。

**阶段 A（开发前）**
1. 新开一个会话，粘贴角色卡全文 + 你的需求描述（或需求文档内容）；
2. 收《需求漏洞清单》→ 回主会话/主工具修正需求（🔴/🟠 必修）；
3. 按报告规范落**报告骨架**（状态行"进行中·第 0 轮·下一动作=开发"；可预见免 C 的任务不建；A 豁免且将走 C 的任务进 C1 前补建；豁免/零 diff/放弃收场须收口为 PASS·免审 / 作废·原因）——隔天/换人续作全靠它。

**阶段 B（开发）**
正常开发；结束后跑一次自测门（有的类型检查/测试/构建就跑，缺项注明）。

**阶段 C（开发后）**
1. 新开另一个会话，粘贴角色卡全文 + 改动文件列表 + 关键代码（或仓库访问方式）；
2. 收《发现表》（含复现步骤）→ **立即补全报告**（骨架已在阶段 A 落盘，A 豁免任务为进 C1 前补建；状态行更新
   "进行中·第 1 轮·下一动作=…"）；
3. 主会话按严重度处置：🔴/🟠 修复 → 先重跑相关定向自测 → 回到本阶段第 1 步重审
   （**每轮都开新会话，附上轮报告**与修复说明）；🟡/🔵 记录；全清 → PASS；
   累计 5 轮（初审计计第 1 轮）仍未全清 → 状态行置"终局·分歧（第 N 轮）"停下汇报，
   同一问题连续 3 轮未收敛可提前停；
4. 状态行改 PASS 终态归档（按 `examples/report-template.md`），宣布"已实现且已通过
   对抗审查"；隔天/换人中断后，收集报告目录全部"进行中"报告（已确认保留/收口的
   孤儿降权让位）：仅一份取之、多份枚举让用户选；对得上判据与他人提交排除见
   SKILL.md 0.1 冷启动续作细则；按状态行续作（"终局·分歧"点名可续作；"已审计·
   待修 N 项"/作废报告可被点名翻回进行中转修复）。

## 只读铁律在纯对话下的落实

- 永远不要给对抗会话写权限/让它输出"修改后的文件"，只要《清单/发现表》；
- 对抗会话的产出是**文本结论**，粘贴回主会话统一处置；
- 每轮重审开**全新会话**（旧会话有记忆偏差，不再是"独立上下文"）。

## 多人/多工具协作提示

同一套角色卡与报告规范可跨工具混用（例如 Claude 审需求、GPT 攻实现）——
文件名规则与严重度定义是全工具统一的协作协议。
